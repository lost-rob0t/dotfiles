#+title: Termux Doom Profile
#+startup: overview

* Purpose

This is the Android/Termux development profile.  It reuses the desktop Doom
configuration in =.doom.d/= as its base -- the same modules, packages, and
config behavior -- instead of keeping a second parallel feature set.  The
desktop tree is only ever read from the dotfiles checkout, never modified, so
desktop Doom usage is unchanged.  The profile launches only on Termux, through
the Chemacs =termux-doom= profile (see =../../emacs/profiles.org=) or the
=emacs-termux= / =doom-termux= wrappers from the bootstrap.

The canonical source is [[file:config.org][config.org]].  Tangling it produces =init.el=,
=packages.el=, and =config.el=.

* Desktop reuse and Android adaptations

=config.org= structures each tangled file as: Termux base definitions, then a
read-only load of the desktop =.doom.d= output, then Android overrides that
always win on the phone.

- =init.el= mirrors the desktop =doom!= selection.  The only deviations are
  Android-hostile native builds: =vterm= (libvterm), =pdf= (poppler), and the
  =+tree-sitter= flags on =json= and =javascript= (grammar compilation).
- =packages.el= loads the desktop =.doom.d/packages.el= as-is.  Nothing is
  redeclared or disabled; desktop packages whose external binaries do not
  exist on Android simply stay dormant.
- =config.el= locates the desktop directory through
  =$STAR_DESKTOP_DOOMDIR=, the =.doom.d= sibling of =doom-private-dir= in
  the checkout, or =~/.dotfiles/.doom.d= / =~/dotfiles/.doom.d=.  It also
  pre-binds =nsa/lisp-directory= from the checkout root so the desktop
  load-path setup works from any checkout location.  Desktop paths that must
  differ on the phone (org root, =org-roam-directory=, =org-configs-list=,
  Eshell aliases, browser handling, alert backend, startup buffer) are
  re-asserted afterwards.

* Focus

- StarIntel admin Org workspace;
- Org editing, agenda, capture, and TODO viewing;
- SWI-Prolog, SBCL, Nim, Python, and shell workflows through native Termux;
- =ob-http= for Org HTTP/admin notebooks;
- gptel inside Emacs;
- OpenCode through the =ai= command and the Debian PRoot compatibility layer.

* Commands

#+begin_src sh
emacs-termux
doom-termux sync
platform-enter --info
platform-enter
ai
#+end_src

=platform-enter= enumerates the host and automatically enters the configured
Debian PRoot only on Termux.  On ordinary Linux/NixOS/WSL it executes directly
on the current host.

* Org paths

The profile checks these locations in order:

1. =$STAR_ORG_ROOT=;
2. =~/Documents/Notes/org=;
3. =~/storage/shared/Documents/Notes/org=;
4. =~/.local/share/org=.

The desktop configuration's org directories are redirected under the selected
Termux root, and agenda files are refreshed recursively, preferring the
=agenda/= subtree when it exists.  The StarIntel admin command checks
=$STARINTEL_ADMIN_ORG= first, then common locations under the Org root and
=~/src/starintel-server=.  If none exist it creates =starintel-admin.org= in
the selected Org root.

* Termux:Widget

The bootstrap creates foreground shortcuts in =~/.shortcuts= for StarIntel
Admin, Org Agenda, TODOs, AI, and platform diagnostics.  Background sync jobs
live in =~/.shortcuts/tasks=.

The Termux:Widget Android app must be installed from the same signing/source
family as the Termux app.  The bootstrap refreshes widgets automatically when
the plugin is detected.
