#+title: Android Emacs Profiles

* Scope

Android has two intentionally separate everyday Emacs environments plus the
existing Temple compatibility profile.

The native Android profile is a lightweight, touch-first, Vim-first Org reader.
It does not boot Doom.  The full Termux development environment continues to
use Doom under =android/doom/=, so the desktop/Termux Doom feature set is not
reduced to make the mobile reader small.

Canonical sources:

- [[file:config.org][config.org]] owns the modern native Org/Vim layer, Stow wrapper, installer, and tests;
- [[file:early-init.org][early-init.org]] owns =early-init.el= and the guarded Termux executable/Bash bridge; =init.el= remains the base native reader entry point;
- [[file:build.org][build.org]] owns =build.py=, the shared local/CI APK build and signing gate;
- [[file:doom/config.org][doom/config.org]] owns the Termux Doom profile;
- =../emacs/profiles.org= owns the Chemacs profile map;
- =../bootstrap-termux.org= owns the Termux bootstrap.

* Native Android Org reader

Default reader startup loads built-in Org plus the existing lazy =org-roam= and
=gptel= integrations.  The modern layer adds =evil=, =evil-collection=, and
=org-modern=.  Vim normal state is the default interaction model and Org gets
mobile-friendly navigation without copying the desktop Doom configuration.

The native touch toolbar is intentionally Org-centric:

#+begin_example
Home   Up   Down   Fold   Open   Todo   Sync   Back
#+end_example

Android touch behavior also enables context menus, precision scrolling, the
software-keyboard integration, and the native modifier bar when available.

* Install with Stow -- no Doom

After the dotfiles checkout exists, a normal same-home install can use:

#+begin_src sh
stow -d ~/.dotfiles/android/stow -t ~ android-emacs
#+end_src

On the paired Android/Termux build, run this from Termux instead:

#+begin_src sh
android-emacs-stow
#+end_src

When the paired native Emacs app is installed and its data directory is
writable, the helper automatically targets =/data/data/org.gnu.emacs/files=
rather than Termux's =$HOME=.  This creates the native Emacs
=.emacs.d/early-init.el= and =.emacs.d/init.el= Stow links in the correct app
home.

The wrappers resolve the real path of those Stow links back into the Termux
=~/.dotfiles/android/= checkout.  Native Emacs therefore does not need its own
copy of =~/.dotfiles= and does not depend on =STAR_DOTFILES_ROOT= being injected
into the GUI process.

Use =EMACS_ANDROID_HOME= only when you need to override the detected native
Emacs home:

#+begin_src sh
EMACS_ANDROID_HOME=/path/to/native-emacs-home android-emacs-stow
#+end_src

The Stow wrapper loads only the repository Android profile.  It does not load
=~/.config/emacs=, =DOOMDIR=, or Doom core.

* Profile switching

Chemacs remains the profile router.  The generated =.emacs-profiles.el= is
owned by =emacs/profiles.org=.

#+begin_src sh
emacs --with-profile android     # native Org-first profile
emacs --with-profile org         # alias for the native Org-first profile
emacs --with-profile doomemacs   # full desktop Doom
emacs --with-profile termux-doom # full Termux Doom
emacs --with-profile temple      # Temple compatibility
#+end_src

The =android= and =org= profiles point at the Doom-free Stow wrapper.  Doom
profiles keep their existing configuration roots and features.

* Termux development bootstrap

For a fresh Termux install, run:

#+begin_src sh
curl -fsSL https://raw.githubusercontent.com/lost-rob0t/dotfiles/master/bootstrap-termux.sh | bash
#+end_src

The bootstrap:

- enumerates Android, Termux, kernel, and CPU architecture before installation;
- performs a full rolling Termux package upgrade;
- installs Git, Emacs, GNU Stow, GitHub CLI, SSH, ripgrep, fd, SQLite,
  SWI-Prolog, Nim, Python, compiler tools, and SBCL on supported 64-bit Android;
- clones or fast-forwards =~/.dotfiles=;
- installs =platform-enter= for the Linux/glibc compatibility guest;
- installs OpenCode in that guest and exposes =opencode= and =ai=;
- preserves the full Termux Doom setup under =~/.config/emacs= with
  =android/doom/= as its =DOOMDIR=;
- creates =emacs-termux=, =emacsclient-termux=, and =doom-termux= for Doom;
- creates =emacs-org= for the Doom-free Org-first profile;
- creates =android-emacs-stow= for installing the native profile;
- installs Termux:Widget shortcuts and background sync tasks.

Useful commands:

#+begin_src sh
platform-enter --info
emacs-org
emacs-termux
doom-termux sync
android-emacs-stow
android-emacs-doctor
git --version
swipl
sbcl
nim --version
python --version
ai
#+end_src

Native development tools stay native to Termux.  The PRoot guest remains only a
compatibility boundary for tools that need a normal Linux/glibc userspace.

* Paired Android Emacs + modern Termux build

The canonical build instructions and implementation are in [[file:build.org][build.org]].
=../.github/workflows/android-emacs-release.yml= builds native GNU Emacs 30.2
for arm64, minimum Android API 29, with =--with-shared-user-id=com.termux=.
It also builds Termux, Termux:API, Termux:Widget, Termux:Boot, Termux:Float,
Termux:Styling, and Termux:Tasker from their current stable source releases.  The workflow records each source commit in =SOURCE-LOCK.txt=.
Manual builds, the existing weekly schedule, and =android-emacs-v*= tags use
the same =build.py= cross-build, signing, and verification entry points.

Normal builds require the repository secrets =STAR_ANDROID_KEYSTORE_B64= and
=STAR_ANDROID_KEYSTORE_PASSWORD= for one persistent private signing identity.
Missing or partial signing configuration fails before compilation.  A manual
=allow_public_test_key= opt-in can produce a TEST-ONLY artifact with the public
Emacs key; that key is not a trust anchor and cannot publish a tagged release.
Do not commit a private keystore or its password.

The signing gate checks actual APK package identities, =com.termux= shared-user
manifests, ZIP alignment, and exactly one identical signing certificate across
the eight applications.  It rejects conditional shared UIDs, wrong/missing
packages, and mixed signers.  Original APKs are preserved; staged outputs are
verified before publication.  =PAIRING.json= contains hashes and signer metadata.

The release bundle contains:

#+begin_example
emacs-android-starintel.apk
termux-starintel-arm64.apk
termux-api-starintel.apk
termux-widget-starintel.apk
termux-boot-starintel.apk
termux-float-starintel.apk
termux-styling-starintel.apk
termux-tasker-starintel.apk
bootstrap-termux.sh
SOURCE-LOCK.txt
PAIRING.json
SHA256SUMS
README.org
BUILD.org
#+end_example

Back up Termux home, packages, and Emacs files before switching signing families.
Android cannot upgrade across incompatible signatures or change an installed
app's shared UID.  Uninstalling can delete app data: the build never installs or
uninstalls anything automatically.  Install the matching family together,
launch Termux and Emacs once, bootstrap the development packages, then run
=android-emacs-stow= from Termux.

The bridge in [[file:early-init.org][early-init.org]] adds the accessible Termux bin directory
to =PATH= and =exec-path= and selects Termux Bash for =M-x shell= and subprocesses.
It sets =SHELL= and =PREFIX= but retains native Emacs HOME and does not change
=LD_LIBRARY_PATH=, =LD_PRELOAD=, or Emacs's Android executable-loader setting.
Repeated initialization is idempotent.  Desktop and inaccessible Termux installs
are unchanged.  Run =android-emacs-doctor= from Termux after =android-emacs-stow=.  It checks
the complete eight-app family, confirms Termux and native Emacs resolve to the
same Android UID, verifies the native profile links, and checks the Termux
toolchain exposed to Emacs.  Then test =M-x shell= and =M-! git --version= in
native Emacs; host-side build verification does not replace a physical-device
smoke test.

Git comes from the paired Termux userspace, not a separately maintained binary
in the Emacs APK.  Optional Emacs libraries and NixOS build-host requirements
are documented in [[file:build.org][build.org]]; full native-library parity and universal Android
compatibility are not implied by successful signing.

* Termux Doom

The canonical phone Doom source is [[file:doom/config.org][doom/config.org]].  It
tangles to =doom/init.el=, =doom/packages.el=, and =doom/config.el=.

The profile keeps StarIntel admin Org workspaces, agenda/TODOs, habits, Babel,
SBCL/Common Lisp, SWI-Prolog, Nim, Python, =ob-http=, Magit, Eshell, and gptel.
Leader shortcuts include =SPC o A= for StarIntel admin, =SPC o a= for agenda,
=SPC o t= for TODOs, and =SPC o i= for AI.

* Termux companion apps

Use the companion APKs from the same paired release as the installed Termux app.
Termux plugins must use the same signature/shared-user family; do not mix this
bundle with plugins signed by another distribution.

- Termux:API bridges shell commands to Android APIs and permissions.
- Termux:Widget exposes foreground scripts from =~/.shortcuts/= and background
  jobs from =~/.shortcuts/tasks/=.
- Termux:Boot runs explicit scripts from =~/.termux/boot/= after Android boot.
- Termux:Float provides a floating terminal overlay for quick admin work.
- Termux:Styling provides the Android terminal font/color picker.
- Termux:Tasker lets Tasker/Locale-style automation invoke allowed Termux
  commands; Tasker itself is not part of this bundle.

The bootstrap creates the Widget shortcuts and background jobs.  Foreground
entries include StarIntel Admin, Org Agenda, TODOs, AI, platform diagnostics,
and the Doom-free Org Viewer.  Background tasks update dotfiles and run the GPT
TODO sync helper.

See [[file:../docs/wiki/termux.org][the Termux companion-app wiki]] for package identities, source-locking,
install invariants, plugin-specific behavior, and troubleshooting.

* Storage and Org files

The Termux Doom profile looks for Org data in this order:

1. =$STAR_ORG_ROOT=;
2. =~/Documents/Notes/org=;
3. =~/storage/shared/Documents/Notes/org=;
4. =~/.local/share/org=.

Agenda files are refreshed recursively, preferring the =agenda/= subtree when it
exists.  The native reader keeps its research roots configurable through
=$STAR_AUTO_RESEARCH_ROOT=, =$STAR_DOTFILES_ROOT=, and =$STAR_GITHUB_OWNER=.

* Repairing a partial Termux upgrade

Termux is rolling-release and partial upgrades can leave native libraries
ABI-incompatible.  If =curl= or Git HTTPS fails with =CANNOT LINK EXECUTABLE= or
a missing SSL symbol:

#+begin_src sh
unset LD_LIBRARY_PATH
apt update
apt full-upgrade -y
apt install --reinstall -y openssl libngtcp2 libcurl curl git
hash -r
#+end_src

* Research repositories

The native reader's =Sync= action calls =bin/sync-auto-research=.  It updates the
current dotfiles checkout and asks =gh= for non-archived repositories owned by
=lost-rob0t= whose names contain =auto-research=.  Existing clones receive a
fast-forward-only pull; missing repositories are cloned under
=~/src/auto-research/= by default.

* Reader dashboard

Startup opens =*Star Research*=.  It scans only the first 32 KiB of each Org file
for metadata and sorts by =#+last_modified=, =#+updated=, =#+created=, or file
modification time.  Reviewed terminal states are =APPROVED=, =IMPLEMENTED=,
=REJECTED=, and =ARCHIVED=.

* Org-roam and GPTel

The =Roam= action lazily loads the canonical
=starintel-auto-research/lisp/starintel/second-brain.el=.  The =GPT= integration
loads only the shared =lisp/llm/ai.el= backend and personas needed on Android.
Secrets remain in the existing auth-source/OpenRouter setup; no API keys are
stored in this profile.

* Temple compatibility

The Chemacs =temple= profile sets =TEMPLE_MODE=active=.  The common Android
wrapper then dispatches to =android/temple/init.el=.  Neither the native reader
nor the Termux Doom profile removes Temple.
