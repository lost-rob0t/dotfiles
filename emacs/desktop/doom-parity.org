#+TITLE: Doom -> Native Desktop Parity Contract
#+STARTUP: overview

This is the acceptance contract for replacing the desktop Doom runtime.
A package being present is not parity.  A module is done when its user-visible
behavior is reproduced natively and covered by a smoke test or an explicit
manual check.

Doom remains the default profile until the pending entries below are closed.

* Languages
The native closure carries the packages selected by the old Doom modules rather
than only the packages named in =~/.doom.d/packages.org=.  The current startup
also restores the high-use runtime paths for CC, Common Lisp/Sly, Emacs Lisp,
JavaScript/TypeScript, Nim, Nix, Org/Org-roam, Python, shell, web, JSON,
Markdown, PHP, and data files.

Language parity is still *PENDING-MANUAL* until each major mode is opened on
=unseen@flake= and its Evil, completion, syntax, formatting, lookup and LSP
behavior is exercised.  That manual pass is required before the default profile
may switch.

* Merge gate
PR #232 is mergeable only when all of these are true:

1. Every Nix fixed-output source hash is real; no =lib.fakeHash= remains in the
   native Emacs closure.
2. Literate tangling produces a clean tree.
3. =tools/doom-parity-smoke.el= passes against the exact Home Manager Emacs
   closure without loading the Doom runtime.
4. Every =PENDING-BEHAVIOR= entry above is implemented or explicitly shown to
   be intentionally unnecessary for the old configuration.
5. The native profile is launched on =unseen@flake= and visually/behaviorally
   compared against Doom: theme, modeline, Agenda startup, Evil motions,
   leader menus, completion, project navigation, workspaces, popups, Magit,
   Org, vterm/eshell, Lisp editing, and LSP.
6. Only after that manual comparison does plain =emacs= switch away from Doom.
