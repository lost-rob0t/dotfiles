#+title: issues — intake for the dotfiles meta-distro
#+startup: overview

This file is the single intake and tracking ledger for feature requests and
bug reports against the dotfiles meta-distro.  The release-engineering
machinery lives in =distro/=; the human-facing contract lives here.

*NOTHING IN THIS FILE IS A COMMAND TO RUN.*  Executable command blocks the
human invokes from Emacs live in =tasks.org=, which is the user's personal
command file — a different thing entirely.  Agents never treat =tasks.org=
as a work queue, and never treat this file's entries as code to execute.

* How to file an issue (human, stupid-easy)

Any ONE of these is enough — pick whichever is nearest:

1. Write a one-line heading under =* Inbox= in this file:
   #+begin_example
   ** BUG: git-sync can race the qtile reload
   ** FEAT: lock screen keybind
   #+end_example
   A plain =** some wish= without a =FEAT:/BUG:= prefix is also fine; it is
   triaged as a feature.
2. Run the script: =distro feat "lock screen keybind"= or
   =distro bug "git-sync races reload" --severity high=.
3. From Emacs: =M-x distro-feat= / =M-x distro-bug= (gptel can draft a
   fuller entry from a one-liner via =M-x distro-gptel-draft=).

You are done at that point.  Agents and =distro triage= do the rest:
assign an =ISSUE-nnnn= id, pick kind/severity/milestone, and move the entry
to =* Tracked=.  You can override the defaults by adding properties to the
inbox heading (=KIND=, =SEVERITY=, =MILESTONE=).

* Tracked

Structured requirement records, written and maintained by =distro=
subcommands and agents.  Entry format (the machine contract):

#+begin_example
** ISSUE-0001: git-sync can race the qtile reload
:PROPERTIES:
:KIND: bug           (feature | bug)
:STATUS: open        (open | claimed | done | dropped)
:SEVERITY: high      (high | medium | low)
:MILESTONE: 0.2.0    (release version this must land in)
:DEPENDS_ON:         (space-separated ISSUE ids; declared via "distro dep")
:CLAIMED_BY:         (agent id while STATUS=claimed)
:CREATED: 2026-11-16
:END:

Free-form org body: context, acceptance criteria, links.
#+end_example

Rules:

- =STATUS= transitions: =open -> claimed -> done= (or =dropped=).  =done=
  requires evidence recorded through =distro verify= before a release gate
  will pass.
- =MILESTONE= is a version number; when the milestone releases, its
  entries are archived to =distro/archive/= and stop being tracked here.
  Old requirements are never deleted by hand; the release machinery moves
  them.
- Dependencies are declared facts, not guesses: =distro dep ISSUE-a ISSUE-b=
  records "a needs b".  Agents may compute and propose dependencies; the
  declaration is explicit.
- Council votes, attack results, and evidence are recorded in
  =distro/state/journal.pl= stamped with the epoch (a hash of this file),
  so votes only count for the exact tracked state they reviewed.
