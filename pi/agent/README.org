#+TITLE: Pi coding agent configuration

Canonical home for the [[https://pi.dev][pi]] coding-agent user configuration on
Termux (pi runs natively; see =docs/wiki/termux.org=).

* Layout

| File/Dir         | Purpose                                                       |
|------------------+---------------------------------------------------------------|
| =settings.json=  | Model defaults, =enabledModels= cycling patterns, skills paths |
| =models.json=    | Custom providers (NanoGPT: =https://api.nano-gpt.com/api/v1=) |
| =mcp.json=       | Global MCP servers (prolog-mcp, brave-search)                  |
| =AGENTS.md=      | Global agent policy loaded across working directories          |
| =prompts/=       | Slash-command prompt templates                                 |
| =extensions/=    | pi extensions (=rlm-ops=: background processes, sub-agents,    |
|                  | shared Prolog blackboard, enforced symbolic verification,      |
|                  | Prolog-RLM frontend)                                           |

* Deployment

=~/.pi/agent/<name>= is a relative symlink to
=../../dotfiles/pi/agent/<name>= for every managed entry.  Relative symlinks
resolve both natively and inside the PRoot guest; Nix store symlinks would
dangle for the native Termux pi process, so Home Manager does not own these
paths.  To install from a fresh checkout:

#+begin_src sh
cd ~/.pi/agent
for f in settings.json models.json mcp.json AGENTS.md; do
  ln -sfn ../../dotfiles/pi/agent/$f $f
done
ln -sfn ../../dotfiles/pi/agent/prompts prompts
ln -sfn ../../dotfiles/pi/agent/extensions extensions
#+end_src

* Local-only state (never in Git)

- =auth.json= — provider API keys and OAuth credentials
- =sessions/= — session transcripts
- =models-store.json= — fetched model catalog cache
- =*.bak.*= — pi-generated settings backups

API keys resolve at request time via pi's =!command= =apiKey= support.  The
NanoGPT key lives in =~/.config/nanogpt/api-key= (mode 600) and is referenced
as =!cat ~/.config/nanogpt/api-key= from =models.json=.

* NanoGPT provider

Curated model list with per-model pricing and context windows taken from the
=GET /api/v1/models?detailed=true= catalog.  IDs are nested (for example
=z-ai/glm-5.3-uncensored=), so =enabledModels= patterns in =settings.json=
need two path segments: =nanogpt/z-ai/*=, not =nanogpt/*=.  Refresh the
catalog with:

#+begin_src sh
curl -sH "Authorization: Bearer $(cat ~/.config/nanogpt/api-key)" \
  "https://api.nano-gpt.com/api/v1/models?detailed=true"
#+end_src

* rlm-ops extension

=extensions/rlm-ops/= is the operations extension for the agent itself: it
gives pi background processes with finish events, sub-agents that share a
Prolog blackboard, an enforced symbolic verification mode, and a frontend to
the Prolog-RLM runtime. It loads for every pi session (including headless
=-p= children spawned by =agent_spawn=, which is how sub-agents share the
same toolset).

** Background processes and finish events

- =bg_run= starts a shell command detached from the turn and returns a task
  id immediately. When the process exits, the extension delivers an event
  message into the session (status, exit code, duration, output tail), which
  triggers the next agent run — the agent receives the event without
  polling. =bg_wait= blocks on a task synchronously when that is more
  convenient (for example inside codemode scripts).
- =bg_list=, =bg_logs=, =bg_kill= inspect and control tasks; =/bg= lists
  them for the user. Tasks are children of the pi process and are killed at
  session shutdown.

** Sub-agents and the shared Prolog blackboard

- =agent_spawn <prompt>= runs a headless =pi --print --no-mcp= child with
  the given task. Children load this same extension; nesting is capped at
  depth 1 — grandchildren must coordinate through the blackboard instead.
- All agents in one orchestration share a blackboard file
  (<session-home>/=shared.pl=, created under =~/.cache/pi-rlm-ops/= unless
  =PI_RLM_OPS_HOME= is set). Children inherit it via =PI_RLM_OPS_KB=.
- =kb_post= / =kb_take= are mailboxes (=msg(From, To, Kind, Payload, Seq,
  Stamp)= facts); =kb_query= / =kb_assert= / =kb_retract= share arbitrary
  facts. Every operation is a flock-guarded one-shot =swipl= run against
  =extensions/rlm-ops/kb_driver.pl=, so state is shared across processes
  and survives agent restarts within the session.

** Symbolic mode (/symbolic)

=/symbolic on|off|status= (or =pi --symbolic=) enables:

- *Observation hooks*: every meaningful tool execution is appended as
  =obs(N, tool(Tool), summary(Text), ok(Bool), stamp(Ms)).= to
  <session-home>/=observations.pl=. Observations are machine-written only.
- *Enforced verification*: at settle time a fail-closed gate
  (=extensions/rlm-ops/gate_driver.pl=) evaluates every declared
  =requirement(Name, Goal)= against recorded observations plus
  agent-declared derivation rules. Unproven requirements block settling
  with a continuation describing exactly what failed (max 4 rejections,
  then it settles and reports failure). =verify_require= declares
  requirements, =verify_rules= adds derivation clauses (validated
  fail-closed: directives and DCG rules are rejected), =verify_drop=
  removes a requirement, =verify_status= runs the gate on demand.
- The agent prompt gets the Prolog-RLM loop contract injected (query →
  hypothesize → observe → record → re-query).

** Prolog-RLM frontend

=rlm_ask= / =rlm_status= drive =lisp/llm/prolog-rlm-bridge.pl= (the same
trusted bridge the Emacs gptel tool uses): the inner runtime does bounded
recursive context inspection with OpenRouter subcalls without loading the
context into the outer conversation. Configuration:

- =PI_RLM_ROOT= — prolog-rlm checkout containing =prolog/rlm.pl=
  (candidates: =~/Documents/Projects/prolog-rlm=,
  =~/dev/lost-rob0t/prolog-rlm=).
- =OPENROUTER_API_KEY= (or =~/.config/openrouter/api-key=) and optional
  =PI_RLM_MODEL= (default =openrouter/auto=).
- =PI_SWIPL=, =PI_RLM_BRIDGE= override the interpreter and bridge path.

** Termux/SWI-Prolog quirks honored here

- =predicate_property/2= misreports Name/Arity indicators on the
  arm64-android build, so the kb driver tracks shared predicates in a
  =board_pred/2= registry instead.
- =call_with_time_limit/2= breaks =findall/3= backtracking on this build;
  timeouts are enforced by killing the swipl process.
- =swipl script.pl other.pl= *consults* trailing =.pl= arguments, so all
  driver arguments travel as JSON in the =KB_ARGS= / =GATE_ARGS=
  environment variables, never as positional argv.

Contract tests: =tests/pi-rlm-ops.sh= (drivers, TS modules, extension load
smoke) runs in CI (see =.github/workflows/nix.yml=).
