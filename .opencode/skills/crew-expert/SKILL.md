# Non-optional crew contract

The coordinator bakes this skill, the protocol and their SHA-256 identities into
EVERY root and child worker. Skill availability alone does not load an expert.

Use **ARADR**, not RAGE or Consortium's separate historical ADARD sequence:
research -> adversarial_review -> analysis -> design -> design_review -> promotion.
Only an explicit trusted approval promotes work to develop; verify is separate.
Do not advance phases or mint approval evidence by writing a plausible sentence.
Review the exact immutable artifact independently, not your own claim of success.

Read the task packet: protocol, crew/run, role, parent, phase, selected files,
requested experts and pinned contract/source hashes. The same role may have many
instances. Your role is not your identity and does not permanently pin a repo.

## Expert-system behavior

Use the actual pinned Prolog KB and registered named expert operations to resolve
facts, prerequisites, capabilities, plans and verifiable postconditions. Maintain
hypotheses, evidence, counterevidence, contradictions and unknowns separately.
Break a task into typed subgoals, consult the owning expert, delegate an admitted
subgoal, inspect the result, and verify. Never substitute confident model prose
for an unavailable expert, Prolog proof or runtime-loaded inventory.

Replicas share the same source/version/hash and contracts, but have independent
run contexts. Do not clone an editable shadow KB or rewrite canonical rules from
memory. A required missing expert must report unavailable rather than silently
falling back to an LLM simulation. The built-in crew Prolog module is a local
policy gate, not a claim that the full DotfilesExpert package has activated.

## Delegation

Use the typed **crew** tool: action=spawn, role=<declared role>, turns=<allocation>,
text=<bounded subgoal>. The host supplies all sender/run/generation identities.
A spawn receipt means policy_pending, not a completed child. The coordinator
returns the admitted child ID to the parent's mailbox; child terminal summaries
are unverified context, never an approval or successful effect proof.

Use action=message with a concrete peer target and bounded text. No self-addressed
message, implicit cross-crew broadcast, auto-reply storm, direct raw `task` child,
or bypass around the crew's Prolog admission. Native OpenCode Task is disabled
for managed crew agents so its descendants cannot evade the crew budget/tree.
Do not block all parent worker slots waiting synchronously for children.

## Preserve past Prolog, always

Existing `.pl` bytes and paths are retained. New facts, rules and corrections use
append-only records or fresh versioned source files. Express `supersedes` links;
never delete the evidence behind an earlier conclusion or use `retractall` as a
persistence strategy. In-memory derived caches may be rebuilt, durable sources
may not be silently rewritten. Never reset, clean, squash or force-push history.

All durable Prolog must be committed in Git, including `.prolog/kb/` and `.zara/`
package adapters. `.gitignore` is not a place to hide new KB history. Run the
preservation gate against the actual branch base before handing off a commit.
The crew tool does not grant shell, commit, signing or publication authority.

Keep raw private transcripts and secrets OUT of Git. Persist bounded reviewed
facts/evidence references through the owning KB API; keep append-only provenance.
Never write a generated file instead of its canonical Org source. Never present
mock, source-scan, stale-SHA or unavailable-runtime evidence as a live test pass.
