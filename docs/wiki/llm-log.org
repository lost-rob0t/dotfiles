#+title: llm-log desktop telemetry

* Source map
- [[file:../../.config/qtile/qtile-llm-log.org][Quota pair]] owns =llm_log_client.py= and =qtile_llm_log.py=.
- [[file:../../.config/qtile/qtile-llm-log-graph.org][New API grapher]] owns =llm_log_graph.py= and =qtile_llm_log_graph.py=.
- [[file:../../.config/qtile/qtile-telemetry.org][Runtime installer]] owns =qtile_telemetry.py= and installs old telemetry, then the pair, then the new graph.

The horizontal bar order is =z.AI=, =GPT=, =LLM graph=. The old OpenRouter
widgets and graph remain separate and unchanged. Quota meters use reported
account limits; the graph uses captured completed-request token buckets.
The two domains must not be converted into each other by guessing a plan cap.

* Enablement boundary
The Python llm-log capture service must expose both =/api/v1/quotas= and
=/api/v1/stats/timeline?coverage=fields=. The Common Lisp forwarding executable
is a different runtime and does not expose these APIs. Backend configuration
and credentials belong to llm-log; no secrets are stored in dotfiles.

These changes are repository changes, not a live deployment. Verify the service
with the user's already-authorized account, then reload the installed Qtile
configuration. Missing/offline/expired values are intentionally not green zeros.
