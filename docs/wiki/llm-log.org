* Source map
- [[file:../../.config/qtile/qtile-llm-log.org][Quota pair]] owns =llm_log_client.py= and =qtile_llm_log.py=.
- [[file:../../.config/qtile/qtile-llm-log-graph.org][New API grapher]] owns =llm_log_graph.py= and =qtile_llm_log_graph.py=.
- [[file:../../.config/qtile/qtile-telemetry.org][Runtime installer]] owns =qtile_telemetry.py= and installs old telemetry, then the pair, then the new graph.
- [[file:../../nix/home-manager/mods/llm.nix][Home Manager consumer]] pins the quota-capable Python llm-log package and owns service enablement.
- [[file:../../nix/home-manager/mods/starintel-llm-harness.org][StarIntel LLM harness]] owns worker profiles, Prolog-RLM/GLM execution wiring, z.AI proxy routing, and quota-pacing policy.

The horizontal bar order is =z.AI=, =GPT=, =LLM graph=. The old OpenRouter
widgets and graph remain separate and unchanged. Quota meters use reported
account limits; the graph uses captured completed-request token buckets.
The two domains must not be converted into each other by guessing a plan cap.

* Home Manager wiring
The LLM profile pins llm-log to =692d3820f638c011fc248a7694ecabd72a6e2895=,
whose analytics, quota, Python, Home Manager, and Common Lisp/Tek9/SWI-Prolog
expert contracts passed exact-head CI. This revision also includes historical
expert backfill, bounded live expert queries, and provenance-preserving dataset
export. =llm.quotaTelemetry.enable= defaults to true when the LLM profile is enabled.
This sets =LLM_LOG_QUOTAS_ENABLED=1= on the existing capture service.

The service uses the underlying =config.codex.package=, not the capture wrapper,
and sets =CODEX_HOME= consistently with the Codex module's XDG preference.
Managed ChatGPT authentication must already exist there. Nothing initiates a
new login, buys a plan, or invokes inference. Reported plan metadata is dynamic.
The GPT widget preserves Codex/account meter scope rather than claiming all
ChatGPT web, voice or model allowances are visible.

For z.AI, the optional private runtime environment file defaults to
=~/.config/llm-log/quotas.env= (or the configured XDG config home). Set
=llm.quotaTelemetry.environmentFile= to use another path. It may contain
=LLM_LOG_ZAI_KEY_FILE=/absolute/path/to/private/key= or =ZAI_API_KEY= supplied
privately by the operator. Keep the environment and key files owner-only (0600).
Do not put secret contents in Nix expressions, repository files or widget options.
The leading optional marker in the unit means a missing file does not prevent
llm-log from starting; z.AI remains unavailable until authentication is supplied.

* Bounded corpus maintenance and operator commands
The desktop profile installs =llm-log-query=, =llm-log-backfill=, and
=llm-log-export=.  These are wrappers around the pinned llm-log expert
maintenance interface at =http://127.0.0.1:8788=; clients should use them
instead of opening =~/Documents/AI/proxy/events.jsonl= directly.

The pinned llm-log backfill implementation streams one JSONL record at a time,
persists a contiguous-success checkpoint, and can resume after interruption.
Home Manager enables =llm-log-expert-backfill.timer= by default with a 15 minute
=OnUnitActiveSec= interval.  The service runs only when the corpus exists and
after the main =llm-log.service=.  It uses low CPU/IO priority and a bounded
service timeout.  Set =llm.expertBackfill.enable = false= to disable the timer or
change =llm.expertBackfill.interval= to alter its cadence.

The corpus is expected to grow to tens of gigabytes.  Interactive consumers,
OpenCode commands, Emacs viewers, reports, and future learning jobs must use
bounded indexed/paginated expert queries.  A full-corpus in-memory load is never
a supported design.  The remaining raw analytics scanner is tracked for
replacement by the indexed large-corpus query work in llm-log#99.

OpenCode receives global =/llm-log-query=, =/llm-log-backfill=, and
=/llm-log-export= commands that explicitly preserve this bounded-query rule.
Environment discovery is also centralized:
- =LLM_LOG_CORPUS= points at the append-only corpus;
- =LLM_LOG_EXPERT_ADMIN_URL= points at the loopback maintenance listener;
- =LLM_LOG_EXPERT_DATA_DIR= points at the separate Tek9 state directory.

For the bounded KB learner tracked in llm-log#102, Home Manager preconfigures
=LLM_LOG_LEARN_BASE_URL=https://llm.starintel.actor= and
=LLM_LOG_LEARN_MODEL_SELECTOR=auto:27b=.  The current pinned llm-log does not yet
run the learner.  The future implementation must query =/v1/models= at runtime,
select exactly one provider-reported 27B model, or fail clearly; the Nix
configuration does not guess a model ID or embed credentials.

* Deployment boundary
The Python llm-log service must expose =/api/v1/quotas= and
=/api/v1/stats/timeline?coverage=fields=. The Common Lisp forwarding executable
is a different runtime and does not expose these APIs.

Apply the reviewed Home Manager change, restart the user llm-log service and
reload the installed Qtile configuration. These repository changes do not
activate a live host by themselves. Missing/offline/expired values are not green
zeros. Local integration used synthetic account metadata and offscreen Cairo;
actual provider login and the user's live desktop remain a separate smoke test.


* StarIntel worker admission
The StarIntel harness consumes the same provider-reported =/api/v1/quotas=
snapshot as the desktop meters. It does not infer capacity from the strings
"Pro", "Max", model names, captured token counts, or local request history.

Each GPT and z.AI window must independently admit a new worker. The default
policy retains 10% reported headroom and paces the spendable portion across the
provider's reported window, with a small 5% burst. A stale, missing, unknown, or
expired meter fails closed. Cross-process concurrency and launch intervals are
also bounded locally.

The harness config is generated at =~/.config/starintel/llm-harness.json=.
The default =main= profile uses Codex in a read-only planner sandbox, validates
the returned plan with SWI-Prolog, can allocate up to 15 named specialist worker
slices, executes GLM-5.3 work through Prolog-RLM and the =zai= llm-log prefix,
and requires independent Codex plus GLM reviews. Logical fan-out is separate
from physical provider concurrency: quota pacing, reserve floors, and launch
leases remain authoritative. The
=main-direct-glm= profile keeps the same planner/review gates but executes
through =opencode-worker=.

These controls pace only harness-originated work. Other clients can still spend
the account allowance; their usage is reflected by the next authoritative quota
snapshot.
The Prolog-RLM GLM wrapper reuses the same private runtime credential source as
quota telemetry: =llm.quotaTelemetry.environmentFile=. It accepts only
=ZAI_API_KEY= or =LLM_LOG_ZAI_KEY_FILE= from that file, requires the environment
file and referenced key file to have no group/other permission bits, and never
sources the file as shell code. Secret contents are not serialized into the
generated harness JSON or Nix store configuration.
