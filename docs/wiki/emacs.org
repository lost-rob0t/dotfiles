* Android and profile architecture
Desktop Doom, Termux Doom, and native Android are separate profiles rather than
one configuration pretending every platform has the same constraints.

- [[file:../../emacs/profiles.org][emacs/profiles.org]] owns =.emacs-profiles.el= and routes =doomemacs=,
  =termux-doom=, =android=/=org=, and =temple=.
- [[file:../../android/config.org][android/config.org]] owns the Doom-free native Android layer.  It tangles the
  Stow wrapper, Evil/org-modern layer, native profile installer, and tests.
- [[file:../../android/doom/config.org][android/doom/config.org]] continues to own the full Termux Doom environment.
- [[file:../../bootstrap-termux.org][bootstrap-termux.org]] installs both =emacs-org= and =emacs-termux= launchers.

The Android profile is intentionally read-first: Vim/Evil bindings are always
available, Org gets =org-modern= presentation and mobile navigation, and a
bottom native touch toolbar exposes Home/heading/fold/open/TODO/sync/back
operations.  It does not load Doom.

The Android release workflow builds GNU Emacs with the =com.termux= shared user
ID and re-signs the current Termux app family with the same compatibility key.
This exposes Termux executables such as Git to native Emacs through =PATH= while
keeping =LD_LIBRARY_PATH= unset.  See [[file:../../android/README.org][android/README.org]] for install/signature
rules and the paired release layout.

* Normal edit cycle
1. Edit =.doom.d/config.org= or =.doom.d/packages.org=.
2. Tangle the changed Org file.
3. Inspect =config.el=, =init.el=, or =packages.el= diffs.
4. Run =doom sync= when module/package state changed.
5. Start or reload Doom and exercise the changed feature.

Batch tangle example:

#+begin_src shell
  cd ~/.dotfiles
  emacs --batch \
    --eval '(require (quote org))' \
    --eval '(org-babel-tangle-file ".doom.d/config.org")'
#+end_src

For Android/profile changes, tangle the relevant sources explicitly:

#+begin_src shell
emacs -Q --batch --eval '
  (progn
    (require (quote org))
    (require (quote ob-tangle))
    (org-babel-tangle-file "android/config.org")
    (org-babel-tangle-file "emacs/profiles.org")
    (org-babel-tangle-file "bootstrap-termux.org"))'
#+end_src

* Useful verification
A lightweight structural check can run without booting the full Doom environment:

#+begin_src shell
  emacs --batch -Q \
    --eval '(with-temp-buffer (insert-file-contents ".doom.d/config.el") (emacs-lisp-mode) (check-parens))'
#+end_src

This catches unbalanced delimiters but is not a substitute for loading the configuration under Doom.

For package/module changes:

#+begin_src shell
  doom sync
#+end_src

Android changes are covered by =.github/workflows/android-emacs.yml= for tangle
parity, Elisp structure, ERT, and shell validation.  The separate
=android-emacs-release.yml= exercises the actual Android/Termux packaging path.

* Durable Org-roam save synchronization
The canonical integration is [[file:../../.doom.d/autoload/gpt-todos.org][gpt-todos.org]].
After Emacs saves an =.org= file anywhere below =~/Documents/Notes/org/=,
it starts =gpt-todos-sync --file FILE= asynchronously.  Git/network work therefore
does not block the editor.  The complete Org root is the Org-roam graph; =daily/=
is the dailies directory, Org QL supplies property-based views, and the derived
Org-roam SQLite database stays in the user cache rather than Git.

The shell helper snapshots the exact saved contents before it acquires the shared
sync lock.  This is important when an agenda file is a symlink into the durable
=~/Documents/gpt-todos/agenda/= checkout: the helper can temporarily rewind only
that just-written path, fast-forward from GitHub, restore the saved snapshot,
commit, and push.  Concurrent local/remote edits still fail closed rather than
silently choosing a winner, and failures retain a recovery copy under the user's
state directory.

Home Manager also runs the same helper every five minutes.  Both paths share the
same lock, so the periodic timer and Emacs save hook cannot race each other.

* Roam AI
Roam AI is the gptel-backed LLM layer for Org-roam in desktop Doom.  The
implementation lives in [[file:../../lisp/llm/ai-roam.el][lisp/llm/ai-roam.el]] and the ontology and rights wiring it
consumes live in the Org Roam section of [[file:../../.doom.d/config.org][.doom.d/config.org]].  Those files are the
canonical sources; this page records only architecture and invariants.

The roam graph (the =roam/= subtree under the Org root) is organized into fixed
sections: =starintel=, =osint=, =entities=, =hacking=, =scada=, =ai=, =llm=,
=programming=, =elisp=, =prolog=, =nix=, =android=, =reading=, =media=,
=daily=, =writing=, and =meta=.  The section a note lives in drives two
properties: its editor rights (what the LLM may write there) and its publish
visibility (=daily= is published, while =hacking=, =scada=, and =meta= are
private by default; enforcement of that visibility belongs to the planned
publish pipeline below).

LLM write access resolves through a single gate, in order: the global toggle
=ai/full-editor-rights=, then the per-section rights alist, then the section
default.  Full rights let the LLM edit roam nodes and create =roam:id= links;
=nil= (=outline=) rights restrict it to generating org outlines the user fills
in.  =hacking=, =scada=, =writing=, and =meta= default to full rights; every
other section defaults to outline.  No Roam AI feature may write into the graph
around this gate, and LLM edits land as ordinary buffer edits, so they flow
through the durable save-sync section above.

The shipped commands are =ai/roam-draft-outline= (outline-only drafting, valid
under any rights), =ai/roam-adopt-section= (move a note into a section), and
=ai/roam-toggle-full-editor-rights= (flip the global toggle).
=ai/roam-chat= is a rights-aware gptel sidebar chat under =SPC m y c=
([[file:../../lisp/llm/ai-roam-chat.el][lisp/llm/ai-roam-chat.el]]): it opens a dedicated right side window,
states the note's roam section and resolved rights in plain words in its
system message, and reuses the roam tool surface (=create_roam_id_link=,
=search_notes_semantic=, =index_notes_embeddings=).  Keybinding
philosophy: nothing existing is rebound.  Roam-scoped commands go under the Doom
localleader =SPC m y ...= prefix in org buffers, and global additions only on
free keys under the existing =y= LLM prefix.

Shipped beyond the PR 1 base: the =org-vector= binary is installed via Home
Manager from the pinned vectored-notes flake (=github:lost-rob0t/org-vector=,
see [[file:../../nix/home-manager/mods/org-vector.nix][org-vector.nix]]).  The =search_notes_semantic= and =index_notes_embeddings=
gptel tools in [[file:../../lisp/llm/ai-roam-vector.el][lisp/llm/ai-roam-vector.el]] register on demand.

Layered memory ships in [[file:../../lisp/llm/ai-roam-memory.el][lisp/llm/ai-roam-memory.el]]: per-subject memory
notes live under =roam/llm/memory/= and an append-only =world_fact/9= Prolog log
grows at =roam/llm/memory/kb-facts.pl=, exposed as the =remember_fact=,
=recall_memory=, and =assert_world_fact= gptel tools with every write behind the
rights gate.  =SPC m y m= recalls a subject's memory note interactively.

Named gptel profiles ship in [[file:../../lisp/llm/ai-roam-profiles.el][lisp/llm/ai-roam-profiles.el]]: typing =@roam=
(or =@roam-outline=) at the start of a prompt line applies that profile before
the prompt is sent, and =SPC m y r= applies one interactively.  The =roam=
profile sets the rights-aware roam system message and the roam tool surface;
=roam-outline= pins outline-only behavior.  Applying a profile also registers a
matching gptel preset, and setup runs automatically at startup whenever gptel is
available.

Roadmap items below are planned, not shipped; PR 1 delivers only the section
ontology, the rights resolver, outline drafting, and the adoption helper.

- =roam:id= link repair;
- roam-wide rewrite;
- writing coach;
- publish pipeline (censor pass, =:private:= exclusion, dailies);
- Prolog-backed world KB under =roam/kb/=;
- notes launcher scripts.

* Deciding a project research record
From a tracked =research/*.org= buffer, invoke
=M-x nsa/research-approve-and-push= or =M-x nsa/research-reject-and-push=,
or use =SPC m A= / =SPC m R=.  The command updates only these canonical fields:

#+begin_example
#+approval_schema: prolog-rlm.research-approval.v1
#+approval_state: APPROVED
#+approval_actor: HUMAN
#+approval_evidence: DURABLE-REFERENCE
#+approval_base_commit: 40-HEX-COMMIT
#+approval_base_blob: 40-HEX-BLOB
#+approval_decided_at: 2026-08-27T12:00:00Z
#+end_example

The command rejects dirty repositories, detached HEAD, ambiguous upstreams,
non-GitHub push URLs, noncanonical or duplicate approval layouts, lifecycle
statuses used as approval, and checked legacy markers.  It records
the current HEAD and its exact file blob before editing, runs =git push
--dry-run=, displays the field-only diff and push target, and asks for explicit
confirmation before creating a file-only commit.  It never checks out, creates,
or guesses a branch.  A failed push leaves the verified local commit in place
and reports the error.  Prose and model output never supply approval state.

* Documentation discipline
Put configuration rationale next to the executable Org source whenever it explains a specific setting.  Use this wiki for architecture, ownership, workflow, and navigation.  This keeps the literate config genuinely literate instead of making readers hunt through two competing manuals.
