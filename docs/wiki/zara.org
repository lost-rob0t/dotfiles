#+TITLE: Zara workflow ownership
#+AUTHOR: nsaspy
#+STARTUP: overview

* Runtime status

The =unseen@flake= profile enables the local Zara daemon, desktop client,
wake listener, workflows, and the Qwen3-TTS CPU service. Its existing private
=config.toml= uses the =zara= clone voice. The shared desktop and hunter02
profiles remain disabled. The GPU path remains out of the flake profile while
the driver incident is unresolved.

* Scope
When enabled, the desktop Home Manager profile's =zara.workflows= module
installs non-secret operator workflow defaults and the bounded
=zara-system-update= helper without taking ownership of Zara's mutable private
overlay.

* Configuration ownership
- =.config/zarathushtra/config.pl= is the canonical tracked declarative base layer
  and Home Manager may replace it on activation.
- =~/.config/zarathushtra/config.local.pl= is intentionally not managed by Home
  Manager.  Keep secrets, machine-private facts, experiments, and temporary
  overrides there.  Zara loads it after =config.pl= so local facts win.
- =~/.config/zarathushtra/secrets.env= remains outside Git/Nix and is consumed
  by the existing =zara-server= EnvironmentFile integration.
- =~/.config/zarathushtra/secrets-daemon-clients.env= is generated exclusively
  by =zara-pair= from the platform keyring and consumed by the desktop
  copilot; never hand-edit or track it.

This split is deliberate: reproducible workflows belong in dotfiles; mutable
private state does not.

* Private OpenRouter Lyria music plugin
The desktop profile installs
=nix/home-manager/files/zarathushtra/plugins/lyria.py= as a repo-local Zara
discovery plugin. It is intentionally not selected from or published to the
=zara-plugins= registry. The source still follows the visibility of this
dotfiles repository; "private" here means local/private deployment and
credentials/state outside Git, not hidden source code.

It exposes two Zara tools:

- =lyria_generate_clip= uses =google/lyria-3-clip-preview= for short previews;
- =lyria_generate_song= uses =google/lyria-3-pro-preview= for full songs.

Both tools accept a music prompt plus optional title, lyrics, instrumental mode,
target duration, and one local JPEG/PNG/WebP reference image. Generated MP3
files default to =~/Music/Zara= with mode =0600=. Override the destination with
=LYRIA_OUTPUT_DIR=. Reference images are embedded into the request as data URLs;
the plugin never fetches an arbitrary image URL itself.

The only required credential is the existing OpenRouter key. Keep it in Zara's
owner-private environment file, never in Nix or Git:

#+begin_src shell
# ~/.config/zarathushtra/secrets.env
OPENROUTER_API_KEY=...
#+end_src

Requests set OpenRouter provider =data_collection= to =deny=. Set
=LYRIA_REQUIRE_ZDR=1= in the same private environment file to additionally
require a zero-data-retention route; this may reduce provider availability.
=LYRIA_TIMEOUT_SECONDS= and =LYRIA_MAX_AUDIO_BYTES= bound request time and
generated media size.

Apply and restart after changing the tracked plugin:

#+begin_src shell
home-manager switch --flake ~/.dotfiles#unseen@desktop
systemctl --user restart zara-server
#+end_src

The plugin streams OpenRouter SSE audio, validates and bounds the base64 payload,
and only writes the completed file after a successful =[DONE]= event. Its unit
test uses a fake provider stream, including base64 chunks split at arbitrary
boundaries, so CI never spends OpenRouter credits.

* Qwen3-TTS backend
The =unseen@flake= profile runs the pinned Qwen3-TTS service on CPU at
=http://127.0.0.1:7860=. Zara streams its speech output. Home Manager does
not own =~/.config/zarathushtra/config.toml=, which still selects the =zara=
clone voice from the user's private voice directory.

Merge this table into that mutable file.  Replace its existing =[tts]= table if
present; TOML does not allow two tables with the same name.

#+begin_src toml
[tts]
provider = "qwen3"
endpoint = "http://127.0.0.1:7860"
voice = "zara"
connect_timeout = 5.0
read_timeout = 120.0
total_timeout = 180.0
#+end_src

The =voice= name must reference a registered clone voice or a model speaker;
create a =zara= voice (below) before switching the provider.

Apply and verify the services:

#+begin_src shell
home-manager switch --flake ~/.dotfiles#unseen@desktop
qwen3-tts doctor cpu
systemctl --user restart qwen3-tts zara-server
qwen3-tts status
sudo loginctl enable-linger "$USER"
#+end_src

The =loginctl= command makes the user services start at boot without waiting
for an interactive login.  The first Qwen start pulls the pinned image and
downloads sha256-verified GGUF models (0.6B talker plus 12 Hz codec, about
1.2 GB); later starts are immediate.  Persistent models and reference voices
live under =~/.local/share/qwen3-tts= rather than in this repository.

Create and manage voices from any FFmpeg-supported audio or video source:

#+begin_src shell
qwen3-tts voice add zara ~/clip.mp3 --text "Exact words in the clip."
qwen3-tts voice add guest ~/video.mp4 --start 00:01:12 --duration 12
qwen3-tts voice list
qwen3-tts voice info zara
qwen3-tts voice set-text zara "Corrected exact words."
qwen3-tts voice rename guest narrator
qwen3-tts voice export narrator ~/narrator.wav
qwen3-tts voice remove narrator
#+end_src

Use =--replace= with =voice add= to update an existing name.  Supplying the
exact =--text= persists a same-stem =.txt= transcript next to the voice WAV,
which the server registers for higher-fidelity ICL clone mode; without it the
voice falls back to the x-vector-only path.  After changing =voice= in
=config.toml=, restart =zara-server=; adding or replacing the referenced clip
itself does not require restarting Qwen.

The CPU backend avoids the previously unstable GPU path. Runtime voice
latency and speech quality still require a live check after activation.

* StarIntel search tool
The flake profile installs the dotfiles-owned Zara plugin from
=nix/home-manager/files/zarathushtra/plugins/starintel.py=. It exposes only
read-only =starintel_search= against the public =/api/v1/search= route at
=ingest.starintel.actor=. The route answered during preparation, but a recent
document was not found through text or ID queries; this is tracked in
[[https://git.starintel.actor/starintel-labs/starintel-server/issues/20][server issue 20]]. Target submission and document writes are not exposed by
this plugin while their operator workflow remains unverified.

* Localhost pairing autosync
=zara-pair= gives same-host clients (desktop copilot, CLI) authenticated CURVE
credentials without manual key copying. One run performs the whole loop:

1. probe the platform keyring through the dotfiles keyring expert
   (=.zara/experts/keyring/=), which owns backend enumeration and selection
   and fails closed with no plaintext fallback;
2. reuse (or generate and store) the device CURVE keypair as keyring items
   under =service=zara-daemon=, =account=desktop-<host>=, one item per field;
3. enroll the public key with the running daemon's live security admin
   (=$XDG_RUNTIME_DIR/zarathushtra/zara-control.sock=), no daemon restart;
4. materialize =~/.config/zarathushtra/secrets-daemon-clients.env= (0600,
   shell- and systemd-sourceable) from =remote_listener.ensure=, so endpoint
   rotations are picked up on the next run.

The =zara-pair.service= oneshot re-syncs after =zara-server= starts, and
=zara-desktop.service= wants it and loads the env file (optional, so the
copilot still starts over IPC before pairing). Diagnostics:
=zara-pair --status= (read-only health report); =zara-pair --revoke= removes
the device enrollment. Secrets live only in the keyring and the 0600 env
file; neither Git nor Nix sees them.

* Local assistant on flake
The =unseen@flake= Home Manager profile starts Zara with its owner-private IPC
endpoint for local clients. The Android TCP listener remains disabled until
its remote client and security state are checked separately. The Zara flake
input is pinned; the private =config.toml= stays out of Nix.

Apply the flake user-service configuration with:

#+begin_src shell
home-manager switch --flake ~/.dotfiles#unseen@flake
#+end_src

Verify the local services with:

#+begin_src shell
systemctl --user status zara-server --no-pager
systemctl --user status zara-wake qwen3-tts --no-pager
journalctl --user -u zara-server -n 100 --no-pager
#+end_src

Remote phone pairing is a separate operation and is not implied by these
local service checks.

* Operator workflows
The canonical fact definitions live in
[[file:../../.config/zarathushtra/config.pl][config.pl]].  They cover
Brave/search, Emacs scratch, org-roam daily followed by the existing
=zara-dictate= path, Thunderbird, Tor Browser, Feishin, YouTube Music, GitHub PR
compatibility, Magit project aliases, and =/pol/=.

The Doom Emacs agenda intents render and maintain the same durable agenda
the editor uses:

- =open agenda= opens the org-agenda day view through emacsclient;
- =clear backlog= runs =nsa/org-agenda-clear-backlog=: every overdue
  entry is marked DONE, and repeating =LOOP= entries advance with Org's
  repeat semantics to their next future occurrence while keeping their
  keyword;
- =open capture= opens the Org capture template menu in a new frame.

The 4chan mapping carries a
small explicit alias set for common text/ASR forms; general edit-distance/fuzzy
resolution belongs in Zara Core rather than being simulated by an unbounded
alias list here.

* System update boundary
=update system= resolves to =zara-system-update=.  The helper performs the three
operator-requested steps in order:

1. =pkexec /usr/bin/pacman -Syu=;
2. =git -C "$DOTFILES" pull --ff-only=;
3. =home-manager switch --flake ...=.

A failing step aborts the sequence and the helper never reports complete unless
all three succeeded.  It never embeds or pipes a password and does not add a
passwordless privilege rule.

The default dotfiles checkout is =~/Documents/Projects/dotfiles=.  Override it
with =ZARA_DOTFILES_DIR=; =ZARA_HOME_MANAGER_FLAKE= and
=ZARA_HOME_MANAGER_TARGET= control the Home Manager invocation when needed.
