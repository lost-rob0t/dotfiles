* Flake overview
[[file:../../flake.nix][flake.nix]] is the main Nix entry point.  The repository currently tracks NixOS 26.05 and Home Manager 26.05 inputs.

The flake provides:
- NixOS configurations;
- standalone Home Manager configurations;
- installer applications;
- buildable packages;
- checks;
- a Nix formatter.

The Home Manager tree is split into:
- [[file:../../nix/home-manager/files/][files/]] - file payloads managed by Home Manager;
- [[file:../../nix/home-manager/mods/][mods/]] - reusable modules;
- [[file:../../nix/home-manager/systems/][systems/]] - host/profile composition.

The canonical skills input installs the shared skill catalog into the configured
OpenCode, Claude, and generic Agent Skills user paths (including the
=.agents/skills= path consumed by Codex-compatible clients).  Keep durable skill
changes in the skills repository; this dotfiles repository only selects the input
revision and enables the client adapters.

* GPT TODO synchronization
[[file:../../nix/home-manager/mods/gpt-todos.nix][gpt-todos.nix]] installs the
shared =gpt-todos-sync= command and enables a systemd user timer by default when
Emacs is enabled.  The timer runs the same locked synchronization path used by
the Doom after-save hook, so periodic and interactive synchronization serialize
rather than racing.

The defaults are:
- durable checkout: =~/Documents/gpt-todos=;
- live agenda tree: =~/Documents/Notes/org/agenda=;
- background interval: =5m=.

They are configurable through =gptTodos.repoDir=, =gptTodos.orgDir=, and
=gptTodos.syncInterval=.  Check the timer with:

#+begin_src shell
  systemctl --user status gpt-todos-sync.timer
  systemctl --user list-timers gpt-todos-sync.timer
#+end_src

The old cron installer remains only as a compatibility path for machines not
managed by Home Manager.  The canonical synchronization behavior lives in
[[file:../../scripts/gpt-todos-sync.org][scripts/gpt-todos-sync.org]].

* Nix GUI apps on non-NixOS hosts
Nixpkgs mesa is patched to look for GL/GBM/Vulkan drivers in =/run/opengl-driver=,
a path that only NixOS populates.  On the Arch host (=unseen@flake=) Nix GUI
apps (Firefox, Discord, Electron) therefore fail GPU init and either fall back
to software rendering without WebGL or crash.

[[file:../../nix/home-manager/mods/nix-gl.nix][nix-gl.nix]] (enable via
=nixGl.enable = true=) installs the =nix-gl-setup= helper.  Running it once as
root provisions the driver symlink and a =systemd-tmpfiles= rule so it survives
reboots:

#+begin_src shell
  nix profile install nixpkgs#mesa   # once, if not already in the profile
  pkexec --disable-internal-agent nix-gl-setup
#+end_src

The rule creates =/run/opengl-driver -> ~/.nix-profile=, a stable path that
survives mesa upgrades; system applications ignore this path entirely.  Home
Manager activation warns when the =/etc/tmpfiles.d/nix-opengl-driver.conf= rule
is missing or stale.  The script lives in
[[file:../../scripts/nix-gl-setup][scripts/nix-gl-setup]] with a regression test
in [[file:../../tests/nix-gl-setup][tests/nix-gl-setup]].

* Installer applications
The flake exposes =install-logos= and =install-logos-gui=.  Their shell implementations live under [[file:../../scripts/][scripts/]].

Useful discovery commands:

#+begin_src shell
  cd ~/.dotfiles
  nix flake show
  nix flake check
#+end_src

To build a specific Home Manager activation without switching:

#+begin_src shell
  nix build '.#homeConfigurations."unseen@desktop".activationPackage'
#+end_src

* Switching a Home Manager profile
For an existing machine with Nix installed:

#+begin_src shell
  cd ~/.dotfiles
  home-manager switch --flake '.#unseen@desktop'
#+end_src

If =home-manager= is not installed globally, bootstrap through Nix:

#+begin_src shell
  nix run github:nix-community/home-manager/release-26.05 -- switch --flake '.#unseen@logos'
#+end_src

See [[file:../logos-home-manager-bootstrap.md][Logos Home Manager bootstrap]] for the existing Logos-specific notes.

* AI client modules and Outrun theme
[[file:../../nix/home-manager/mods/llm.nix][llm.nix]] composes the AI client plane, while each client owns its package and client-specific behavior:

The same module exposes the pinned skills input's =youtube-context= executable.
The Doom =SPC y v= command starts it asynchronously and copies its completed
caption-or-Whisper packet to the kill ring and system clipboard, so the
interactive Emacs path and the standalone skill share one output implementation.

| Module | Local options | Complete client configuration |
|--------+---------------+-------------------------------|
| [[file:../../nix/home-manager/mods/opencode.nix][opencode.nix]] | =opencode.enable=, package, native =--auto= usage, and llm-log routing | Home Manager's =programs.opencode=: settings, TUI, web service, context, commands, agents, skills, themes, tools, extra packages, and shared MCP integration |
| [[file:../../nix/home-manager/mods/codex.nix][codex.nix]] | =codex.enable=, package, pinned skills, llm-log routing, and explicit =manageConfig= ownership | Home Manager's =programs.codex=: settings, profiles, context, hooks, plugins, marketplaces, skills, rules, and shared MCP integration |
| [[file:../../nix/home-manager/mods/chatgpt-desktop.nix][chatgpt-desktop.nix]] | =programs.chatgpt-desktop=: package plus dark/light appearance, code-theme, font-size, smoothing, cursor, and diff-marker settings | The desktop application's native =[desktop]= configuration |

[[file:../../nix/home-manager/mods/outrun-theme.nix][outrun-theme.nix]] is the single palette definition.  Its defaults are the Doom/Qtile Outrun colors: deep =#170c32= and raised =#202146= backgrounds, =#f3f4f5= foreground, neon pink =#f6019d=, cyan =#2de2e6=, green =#62ff00=, orange =#fba922=, red =#dd546e=, purple =#9700cc=, and the extended Qtile accents.  Applications consume =outrunTheme.palette= rather than copying color literals.

When =llm.enable= is enabled, all three clients and =outrunTheme= are enabled.  Home Manager writes the user-wide OpenCode JSON theme to =~/.config/opencode/themes/outrun.json= and selects it in =tui.json=.  A project can still override it with =.opencode/themes/outrun.json=, following OpenCode's normal theme precedence.

Codex CLI receives =~/.codex/themes/outrun.tmTheme= and selects it through =[tui].theme=.  ChatGPT Desktop receives the same palette through its native dark chrome theme, with Hack Nerd Font for code and Noto Sans for UI text.  By default, both settings are applied by a narrow, idempotent TOML updater that preserves every unrelated Codex setting and comment.  It refuses to replace a symlinked Home Manager-owned =config.toml=.  Set =codex.manageConfig = true= only after migrating the complete file into =programs.codex=; that opt-in makes Home Manager own =config.toml= and enables shared MCP import.  Restart ChatGPT Desktop after switching the profile so the running app reloads its appearance.

The generated desktop payload at =~/.codex/themes/outrun-desktop.json= is an inspectable record of the managed appearance values.  Authentication, provider credentials, and other runtime state remain outside these theme files and outside the Nix store.

The focused checks are:

#+begin_src shell
  nix build '.#checks.x86_64-linux.ai-client-theme'
  nix build '.#checks.x86_64-linux.codex-config-patch'
#+end_src

* LLM tooling and Brave Search MCP
Enabling =llm.enable= also enables the reusable [[file:../../nix/home-manager/mods/brave-mcp.nix][Brave MCP module]] by default, installs Brave's =bx= CLI plus the typed =brave-mcp= stdio adapter, and exposes that MCP server to OpenCode through the shared MCP Home Manager integration.  A host may still override =braveMcp.enable = false= explicitly.

The Brave Search API key is runtime user state and must not be written into Nix configuration or the Nix store.  After switching the Home Manager profile, configure it interactively:

#+begin_src shell
  bx config set-key
#+end_src

On Linux, =bx= stores its user configuration under =~/.config/brave-search/config.json=.  For ephemeral sessions, =BRAVE_SEARCH_API_KEY= is also supported:

#+begin_src shell
  export BRAVE_SEARCH_API_KEY='...'
#+end_src

Prefer =bx config set-key= without putting the key on the command line so it does not enter shell history.  Verify the CLI before starting OpenCode:

#+begin_src shell
  bx context "NixOS Home Manager documentation" --max-tokens 1024
#+end_src

The MCP adapter exposes bounded, typed search tools rather than arbitrary =bx= argv or shell execution.  Its package lives at [[file:../../nix/packages/brave-mcp/][nix/packages/brave-mcp/]] and its protocol regression test is [[file:../../tests/brave-mcp.py][tests/brave-mcp.py]].

* Editing rule
Host-specific composition belongs under =nix/home-manager/systems/= or =nix/nixos/hosts/=.  Reusable behavior belongs in modules rather than being copied between hosts.  Keep =flake.nix= focused on wiring outputs together.

After Nix changes, run at minimum:

#+begin_src shell
  nix fmt -- --check
  nix flake check
#+end_src

If the formatter invocation differs on the installed Nix version, run =nix fmt= and inspect the resulting diff before committing.
