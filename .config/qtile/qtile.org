#+title: Qtile Configuration

* Canonical configuration
The active Qtile configuration is generated at [[file:config.py][config.py]], but its canonical editable source is [[file:qtile-ai.org][qtile-ai.org]].

Do not make lasting edits directly in =config.py=. Edit =qtile-ai.org= first, tangle it, and commit the generated =config.py= in the same change. The repository-wide literate source rules are documented in [[file:../../AGENTS.md][AGENTS.md]] and [[file:../../docs/wiki/literate-config.org][the dotfiles wiki]].

The OpenRouter telemetry helper follows the same rule: [[file:qtile-openrouter.org][qtile-openrouter.org]] is canonical and generates =qtile_openrouter.py=.

Qtile's screen-capture bindings are kept in [[file:qtile-capture.org][qtile-capture.org]], which generates =qtile_capture.py=. The extension is installed before key telemetry instrumentation so capture shortcuts remain visible in the same keymap telemetry as the main configuration.

Complex click-driven bar panels use the shared [[file:../../docs/qtile-emacs-ui.org][Qtile and Emacs dropdown UI]]
runtime helpers.  The canonical Qtile source still owns bar composition; the
standalone =emacs_ui.py=, system telemetry, Dunst adapter, and =lisp/qtile/=
modules own reusable popup/data behavior.

* Monitor configuration
Qtile's =startup= hook launches =scripts/setup-monitors.sh= on every Qtile start
and restart. The loader looks for an executable host profile named after the
current user and hostname:

=~/.config/qtile/scripts/monitors/USER@HOSTNAME.sh=

If the profile exists, it configures the outputs with =xrandr=. Qtile's
=generate_screens= hook then creates one bar per active output. The system tray
is placed on the physical middle monitor. For an even number of outputs, the
monitor to the right of center receives the tray. The hook also reruns when
Qtile reconfigures screens.

Monitor setup is intentionally not part of =autostart.sh= or =.xinitrc=;
=.xinitrc= only starts Qtile after importing the display environment.

The profile for this workstation is =scripts/monitors/unseen@flake.sh=.

* Emacs popup server
The Qtile startup script checks the named =qtile= Emacs server with
=emacsclient -s qtile -a false=.  If it is absent, it starts
=emacs --daemon=qtile= after the X session has supplied =DISPLAY= and
=XAUTHORITY=.  Popup requests carry the live display to the shared Elisp frame
creator, so a headless daemon can create a GUI frame without starting a second
interactive Emacs window.

* Keybindings
Qtile owns the complete active keymap. The former SXHKD configuration was
retired after its approved shortcuts were migrated to native =Key= entries.

Screen capture is routed through the stable =screen-capture= CLI rather than a
desktop screenshot application. The direct screenshot bindings preserve the
existing layout, while recording uses the thin Emacs picker:

| Binding             | Action                         |
|---------------------+--------------------------------|
| =Print=             | Full screenshot                |
| =Super+Print=       | Select screenshot region       |
| =Shift+Print=       | Open the Emacs recording UI    |
| =Super+Shift+Print= | Stop and finalize recording    |

The CLI owns X11/Wayland backend selection, recorder state, clipboard behavior,
and output paths. See [[file:../../docs/wiki/screen-capture.org][the screen-capture wiki page]] for the full command and Home Manager contract.

Monitor focus and window movement use physical X coordinates, so Left and Right
select the adjacent display instead of following XRandR's output enumeration.

* Automatic group mode
The first button on each top bar always displays =AUTO= in black text.

Its background color indicates the current mode:
- Green means automatic group management is enabled.
- Pink/red means automatic group management is disabled.

Left-clicking the button enables or disables automatic group management.

When enabled:
- Existing mapped windows are immediately moved to their configured groups.
- New mapped windows are moved to their configured groups.
- Moving a mapped window to another normal group is automatically corrected.
- Groups with more than three windows use the =max= layout.
- Groups with three or fewer windows return to their configured default layout.
- Scratchpad windows are excluded.

When disabled, Qtile stops enforcing routes and layout thresholds. Existing windows and layouts are left in their current state so they can be rearranged manually.

Application routes are configured in =auto_group_routes= in =config.py= and therefore must be changed through =qtile-ai.org=.

* Usage telemetry
Qtile appends structured JSONL events to:

=~/.local/state/qtile/telemetry.jsonl=

If =XDG_STATE_HOME= is set, the log is stored under =$XDG_STATE_HOME/qtile/= instead.

The telemetry records:
- the configured keymap at session start
- actual keybind and key-chord usage
- managed, focused, moved, routed, floating, and closed windows
- window title, WM_CLASS, PID, geometry, group, screen, and layout
- group additions and removals
- layout changes and window counts
- group and screen changes
- AUTO mode changes
- Qtile startup, restart, and shutdown events

The log rotates at 25 MiB and retains four rotated files.

Generate a compact JSON report for LLM analysis with:

#+begin_src sh
python ~/.config/qtile/scripts/qtile-telemetry-summary.py > ~/qtile-telemetry-report.json
#+end_src

The report ranks keybind use, focused and managed applications, unmatched applications, common group destinations, layout changes, automatic routes, and group or screen usage.

The raw telemetry includes window titles. Browser page names, document names, terminal titles, and other private information may therefore appear in the JSONL files. Review the raw log or generated report before sharing it.

* Validation
After modifying =qtile-ai.org= or related Qtile sources, tangle first and then run:

#+begin_src sh
python -m py_compile config.py qtile_capture.py qtile_telemetry.py scripts/qtile-telemetry-summary.py
qtile check -c config.py
#+end_src

The second command requires Qtile to be installed in the current environment.
